\section{Conclusion}
\label{sec:conclusion}

We introduced KB, a local-first, facts-first codebase knowledge system that
converts the overhead of maintaining a knowledge base into a side-effect of
normal development work.  KB's deterministic AST indexing, multi-pond BFS
retrieval, and knowledge accretion model produce a system that improves with
use rather than requiring dedicated maintenance.  On the raylib benchmark, pass
rates improve from 0.25 to 0.62 across two runs; on the KB self-check suite,
pass rates improve from 0.38 to 1.00 over a ten-week development trajectory,
with mean correctness and evidence-handling scores reaching 4.00/4.00.

We also introduced MOEL, a multi-objective evaluation framework that measures
agent efficiency along correctness ($L_\text{AST}$ + $L_\text{jury}$),
trajectory ($L_\text{trajectory}$), and resource ($L_\text{resource}$) axes.
MOEL's bias-mitigated jury ensemble, statistical calibration, and programmatic
validators make it possible to distinguish between an agent that answers
correctly by exploring efficiently and one that wastes compute to reach the same
result.

\paragraph{Limitations.}

\textbf{MOEL token-efficiency runs are incomplete.}  The full two-condition
comparison (N vs.\ K, four-task sequence) is in progress.  Preliminary
evidence from single-condition telemetry is encouraging but not yet definitive.

\textbf{Calibration sample size is small.}  The 20-sample human-annotated
dataset is sufficient for per-judge logistic regression but does not support
fine-grained calibration per rubric axis.  A 100-sample dataset with axis-level
labels would significantly strengthen the calibration validity.

\textbf{AST loss is structural, not semantic.}  $L_\text{AST}$ measures
declaration-set overlap, not whether two implementations are behaviorally
equivalent.  An agent that renames every exported symbol would receive high
$L_\text{AST}$ even if the logic is identical.  Combining $L_\text{AST}$ with
execution-based correctness (e.g., test passage) would yield a more robust
correctness signal.

\textbf{Knowledge base scope.}  KB currently operates on per-file ASTs.
Cross-file dependencies (inheritance hierarchies, inter-module call graphs)
are captured through edge relationships but are not modeled explicitly at init
time.  This is shared with all file-level agent interfaces; extending to
whole-repository static analysis is future work.

\paragraph{Future Work.}

\begin{itemize}
  \item \textbf{Full MOEL run completion}: execute the four-task N/K/O comparison,
    report $L_\text{MOEL}$ per condition per task, and test the compounding
    hypothesis quantitatively.
  \item \textbf{Calibration expansion}: grow the human-annotated set to 100+
    samples with axis-level labels; evaluate whether axis-level calibration
    improves jury reliability.
  \item \textbf{Streaming accretion}: integrate \texttt{kb submit} into
    agent loop hooks so that facts are deposited in real time during a session,
    not only at explicit submission points.
  \item \textbf{Cross-language extension}: extend AST indexing and $L_\text{AST}$
    to C (for raylib's primary codebase) and Java; evaluate whether entity and
    relationship density correlates with retrieval quality across languages.
  \item \textbf{Multi-repo knowledge graphs}: explore federated knowledge bases
    where facts from multiple related repositories are connected through
    shared symbol references, enabling cross-repo reasoning.
\end{itemize}

\paragraph{Reproducibility.}

All evaluation artifacts are stored under
\texttt{\textasciitilde/.kb/evaluations/<run-name>/artifact.json} in a
versioned JSON schema.  The canonical question sets are defined in
\texttt{eval/suites/\{raylib,kb,fzf\}.yaml}.  Loss function implementations,
calibration scripts, and the MOEL harness are available in the KB repository
under \texttt{eval/}.
