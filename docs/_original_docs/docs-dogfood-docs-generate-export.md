# kb is a local-first CLI knowledge base: capture facts and docs in SQLite-backed bases, then query and generate so agents pull what the team actually decided.
ID: kb-is-a-local-first-cli-knowledge-base-capture-facts-and-docs-in-sqlite-backed-b
Type: introduction
Tags: docs-generate
Created: 2026-04-28T22:55:33.759Z
Updated: 2026-04-28T22:55:33.759Z
Base: dogfood

kb is a local-first CLI knowledge base. It captures facts and documents in SQLite-backed bases. This allows querying and generation of information so AI agents pull what the team actually decided.

For developers and tech leads using AI coding tools who want grounded, repo-specific context instead of generic guesses.

### Workflow

*   Bases isolate knowledge.
*   Submit and query facts.
*   `init` ingests README and documentation.
*   `docs generate` uses a short checklist, then drafts with references to stored facts.

### Boundaries

*   Not a hosted SaaS product.
*   Not a full IDE replacement.
*   Does not provide automatic correctness without human review.

### Next Steps

*   Initialize a project base: `kb init --base <name>`.
*   Query facts: `kb query`.
*   List and view documents: `docs list`, `docs view`.
*   For agent workflow, see `CLAUDE.md` and `TESTING.md` in the repository.

# Reader can create or refresh a project KB base from existing markdown so kb query and agents return grounded answers for that repo.
ID: reader-can-create-or-refresh-a-project-kb-base-from-existing-markdown-so-kb-quer
Type: howto
Tags: docs-generate
Created: 2026-04-28T22:55:51.414Z
Updated: 2026-04-28T22:55:51.414Z
Base: dogfood

This guide explains how to initialize or refresh a project KB base from existing markdown files in a repository, enabling `kb query` and agents to return grounded answers.

### Prerequisites

*   Node 22+
*   `kb` CLI installed and on `PATH`
*   Write access to the repository and KB home (`~/.kb`)
*   Optional: LLM keys configured for `init` and `docs generate` steps

### Steps

1.  Change directory to your repository:
    ```bash
    cd your-repo
    ```
2.  Initialize the KB base:
    ```bash
    kb init --base <name> --non-interactive
    ```
    (Alternatively, use the interactive wizard without `--non-interactive`).
3.  Select the newly created base for use:
    ```bash
    kb base use <name>
    ```
4.  After editing documents, rescan the base. Use `--rescan --apply` if you want changes written back to the base:
    ```bash
    kb init --base <name> --rescan
    # Or, to apply changes:
    kb init --base <name> --rescan --apply
    ```
5.  Confirm documents have been ingested:
    ```bash
    kb docs list --base <name>
    ```

### Gotchas

*   Large directory trees can make `init` slow.
*   `rescan --apply` changes files; review dry-run output before applying.
*   Use `ci-*` bases for throwaway tests, not for dogfooding.
*   LLM must be configured for LLM-heavy steps.

### Verification

*   `kb docs list` shows ingested documents.
*   `kb query` on a known topic returns hits with citations.
*   No `init` errors appear in the log.
